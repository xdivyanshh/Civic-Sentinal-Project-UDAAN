💡 Living Q&A Knowledge Base (Viva Defense Master Guide)
Q1: How are the 4 OOP Pillars demonstrated in this project?
1. Abstraction: BaseRecord pure virtual methods (calculatePriorityScore() = 0).
2. Encapsulation: Private variables (severity, upvotes, budget) mutated only through guarded member methods.
3. Inheritance: GrievanceRecord, SuggestionRecord, and ComplimentRecord derive from BaseRecord.
4. Polymorphism: Max-Heap stores generic shared_ptr<BaseRecord> pointers and calls specialized priority scoring algorithms dynamically at runtime.
Q2: Why use a Max-Heap instead of sorting an array?
Sorting an array takes Ο(N log N) every time a new complaint arrives or an upvote occurs. A Binary Max-Heap (std::priority_queue) keeps the most acute crisis at the root in Ο(log N) insert/delete and Ο(1) top access.
Q3: How does the Anti-Sybil Vault prevent voter spam?
Uses a Hash Set (std::unordered_set) of composite keys: "CITIZEN_ID::RECORD_ID". It checks in average Ο(1) constant time whether that constituent has already voted for that specific ticket, rejecting duplicate attempts immediately.
Q4: Where is a Balanced Search Tree / Red-Black Tree used?
In TelemetryEngine, using std::map (which is internally an Asymptotically Balanced Red-Black Tree). It stores chronological monthly indicators and performs Ο(log M + K) range queries via lower_bound() and upper_bound() to calculate the politician's 0–100 accountability score.
Q5: What do the Prefix Trie and Inverted Index do?
The Prefix Trie (TagTrie) delivers instant Ο(L) prefix search and autocomplete for municipal tags like "pothole" and "water-contamination". The Inverted Index (DuplicateDetector) tokenizes complaint titles and maps keywords to ticket IDs to alert citizens before creating duplicate tickets in the same ward.
